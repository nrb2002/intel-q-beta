# Milestone 09 — UI, Security & Hardening

## Objective
Make the MVP professional, secure, accessible, responsive, and resilient before deployment.

## Tasks — Security
- [ ] Review every protected API endpoint.
- [ ] Verify server-side authorization.
- [ ] Validate all public request bodies.
- [ ] Validate IDs and configuration references.
- [ ] Prevent arbitrary status manipulation.
- [ ] Prevent arbitrary ticket-number creation.
- [ ] Prevent unauthorized ticket transitions.
- [ ] Handle duplicate submissions.
- [ ] Consider rate limiting for public ticket issuance.
- [ ] Avoid exposing internal errors.
- [ ] Review sensitive logging.
- [ ] Verify secure password hashing remains in place.

## Tasks — UI
- [ ] Standardize buttons.
- [ ] Standardize form fields.
- [ ] Standardize alerts.
- [ ] Standardize loading states.
- [ ] Standardize empty states.
- [ ] Standardize error states.
- [ ] Review typography and spacing.
- [ ] Review mobile layouts.
- [ ] Review tablet/kiosk layouts.
- [ ] Review staff desktop layouts.
- [ ] Review customer display typography.

## Accessibility
- [ ] Verify labels.
- [ ] Verify keyboard navigation.
- [ ] Verify focus states.
- [ ] Verify validation messages.
- [ ] Verify contrast.
- [ ] Verify large display readability.

## Acceptance Criteria
- [ ] No known critical authorization gaps remain.
- [ ] Public endpoints are validated and hardened.
- [ ] UI is consistent.
- [ ] Main workflows work on mobile, tablet, and desktop.
- [ ] Customer display is readable from a distance.
- [ ] No obvious production-blocking errors remain.

## Deliverables
- Hardened MVP.
- Consistent UI.
- Accessibility pass.
- Security review notes.
